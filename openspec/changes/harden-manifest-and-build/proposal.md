## Why

Ostrilo ships two manifests generated by WXT, and neither one has been audited against what a Nostr signer should declare. `.output/chrome-mv3/manifest.json` and `.output/firefox-mv2/manifest.json` declare no `content_security_policy` at all, expose `injected.js` to every http and https origin with a stable URL, and request permissions that were never reviewed as a set. The Firefox manifest is worse than unreviewed: it is invalid, because `sidebar_action` still carries WXT's scaffold placeholder strings.

Production builds also ship 34 `console.log` calls in `background.js`, and `pnpm zip:firefox` would upload a 122 MB sources archive that is 85% local Playwright artifacts, including Chromium profile directories with the extension's own storage. Nothing asserts any of this, so every property above can regress silently on the next build.

## What Changes

- Declare an explicit `content_security_policy.extension_pages` in `wxt.config.ts`, covering `script-src`, `object-src`, `connect-src`, `img-src`, `style-src`, and `default-src`, so the sandboxing a signer depends on is pinned rather than inherited from a browser default.
- **BREAKING (build output)** Fix the invalid Firefox `sidebar_action` block by removing the WXT scaffold placeholder `<meta name="manifest.*">` tags and the placeholder `<title>` from `src/extension/sidepanel/index.html`.
- Move the Firefox target from MV2 to MV3 so the background context is an event-based service worker rather than a persistent page that holds decrypted key material for the whole browser session.
- Strip `console.*` from production builds via an esbuild `drop` setting in `wxt.config.ts`. This change owns the build setting; `remove-key-exfiltration-surface` owns deleting the specific secret-leaking log statement.
- Add `use_dynamic_url: true` to the `injected.js` `web_accessible_resources` entry so a stable extension-relative URL can no longer be probed by arbitrary pages to fingerprint the user as a Nostr signer.
- Apply least privilege to the permission set: drop the redundant explicit `sidePanel` entry (WXT adds it automatically for MV3 and it is not a valid Firefox permission), keep `storage` and `windows`, and review the set as a whole alongside the `alarms` permission that `implement-session-auto-lock` will add.
- Tighten archive and build-output hygiene: an explicit `zip.excludeSources` allowlist, an explicit `zip.exclude` for the extension archive, and removal of the unreferenced 840 KB `icon.png`/`icon.svg` pair from the shipped output.
- Add a build-output assertion test that reads both generated manifests and asserts CSP, permissions, `web_accessible_resources`, content-script matches, and the absence of placeholder strings, so none of the above can regress unnoticed.
- Document what verifiable builds would require and record the reproducibility gap.

This change does not validate relay data or avatar URLs at the application layer; `validate-relay-and-remote-data` owns that. It does not change the injection mechanics in `content.ts`; `harden-provider-trust-boundary` owns that, including the decision to narrow content-script matches. It does not add auto-lock; `implement-session-auto-lock` owns that. No store submission, signing key, or release pipeline ships in this change.

## Capabilities

### New Capabilities

- `extension-manifest-policy`: The security-relevant declarations in the generated manifests, for every build target: content security policy, permission set, web-accessible resource exposure, content-script matches, and cross-browser manifest correctness.
- `build-output-integrity`: What the production build and the published archives are allowed to contain: no debug logging, no source maps, an explicit shipped-file allowlist, and a documented path to verifiable builds.

### Modified Capabilities

- None. No existing spec in `openspec/specs/` states requirements about the manifest, the permission set, or build output.

## Impact

- `wxt.config.ts`: gains `content_security_policy`, `use_dynamic_url`, a revised `permissions` array, an esbuild `drop` setting, and `zip` configuration. Firefox target moves to `manifestVersion: 3`.
- `src/extension/sidepanel/index.html`: placeholder `manifest.*` meta tags and placeholder `<title>` removed; a real side panel title set.
- Build output paths: the Firefox output directory becomes `.output/firefox-mv3`. `package.json` scripts keep their names, but any doc, fixture, or CI step that hardcodes `.output/firefox-mv2` must be updated.
- `src/extension/background.ts`: the Firefox background context becomes non-persistent, so any module-scope state that was implicitly surviving for the session must tolerate suspension. This is the same constraint Chrome already imposes.
- Tests: a new manifest-assertion suite reading `.output/*/manifest.json`. Existing E2E fixtures that load the unpacked Firefox build need the new output path.
- Coordination: `remove-key-exfiltration-surface` must not also add the console-drop setting; `implement-session-auto-lock` adds `alarms` to the permission set and to the manifest assertion; `harden-provider-trust-boundary` determines the final content-script match list that this change's assertion checks.
- Docs: `openspec/project.md` claims "Minimal manifest permissions: only `storage` and `sidePanel`" and "Firefox Manifest V2"; both become inaccurate and need updating.
